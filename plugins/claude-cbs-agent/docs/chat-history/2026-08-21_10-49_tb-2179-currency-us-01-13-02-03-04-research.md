## Learned

- **US-01.13.03 TC-01 contract drift (4 points, all literal-text-level, not infra-level):**
  1. Case says `GET /pricing/rate?market=MM&unit=UUUUUUU&base=USD&quote=EUR&amount=5000&rateType=ASK`; real endpoint is `POST {{currency-engine-url}}/api/v1/currencies/rates` with a JSON body (`market`, `businessUnit`, `baseCurrency`, `quoteCurrency`, `rateType`, `amount: {units, nanos}`). No GET endpoint for rates exists anywhere in Bruno.
  2. Case expects `{baseCurrency, quoteCurrency, rateType, transitCurrency:null, amtFrom, amtTo, rateValue}`; real response is `{baseCurrency, quoteCurrency, rateType, quoteCode, rateValue}` — `transitCurrency`/`amtFrom`/`amtTo` don't exist in the real response at all.
  3. Only `MID`-type rate bands are seeded on QA; `rateType=ASK` returns 404 "Rate Not Found" unless a full async pipeline (INPUT→AUTH→force-schedule, ~45-90s) is run first to create one.
  4. No 401/403 test cases exist anywhere in the Bruno `Currency Engine` collection (only 400/404/422/500 documented) — the "internal system-integration permission" precondition can't be independently confirmed either way.
- The BA's own Confluence page for US-01.13.03 contains an illustrative OpenAPI spec (`GET /exchange-rates/calculate?...` → `{baseCurrency, quoteCurrency, exchangeRate}`) that is itself a *third*, different shape from both the TC text and the real `proj-currency-engine` implementation — the manual QA's `GET /pricing/rate` text was likely copied from that BA spec, not invented; the real gap is a BA-spec-vs-implementation drift that predates the test case.
- `AMT_FROM` band selection (`AMT_FROM <= Amount < Next_Tier_AMT_FROM`) is empirically confirmed live for US-01.13.03/AC4: amount=500→tier 0 (rate 1.0000), amount=5000→tier 0, amount=15000→tier 10000 (rate 2.0000).
- A new negative Bruno test (`INPUT - Reject START_DATETIME Inside The Cutoff Lag`) surfaced in a fresh `proj-bruno-api` fetch, confirming `proj-currency-order-cutoff-plugin` is deployed and working (400, "execution lag buffer") — this resolves a previously-open doubt (from an earlier session/transcript, attributed to "Артур") about whether the cutoff plugin was actually live for US-01.13.02.
- The `Currency Engine` Bruno collection's basic-auth password changed (`proj-admin` → `proj-admin-Strong-123!`) — irrelevant to this suite (Keycloak creds used instead) but worth knowing if anyone drives Bruno manually against that collection.
- Each of the four currency stories (US-01.13.01–04) turned out to have its own dedicated Confluence page, discoverable via `getJiraIssueRemoteIssueLinks` on the Jira ticket — not just a shared section on the EP-01.13 epic page. Prior sessions had only read the epic page.
