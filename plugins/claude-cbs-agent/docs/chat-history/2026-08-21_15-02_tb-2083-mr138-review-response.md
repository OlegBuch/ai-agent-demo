## Learned

- `docs/chat-history/`'s own convention (`.claude/commands/session-summary.md`): one timestamped
  file per session, append-only, never overwritten — this file itself follows that.
- The `playwright/expect-expect` ESLint rule's `assertFunctionNames` list
  (`eslint.config.mjs:46-54`) must be extended whenever assertions move out of a test body into a
  new custom helper function, or ESLint reports a false "Test has no assertions" even though the
  helper does assert internally via `expect`/`expectStatus`.
- `allure-results/*-result.json` (when present locally, e.g. from a recent live run) is a
  reliable, low-effort source of *actual* captured platform response bodies/status codes for a
  specific test step — cheaper and more certain than guessing from the Bruno workspace's static
  request templates, which often lack a saved example response for error paths.
- Two same-named-but-independent functions can coexist in this codebase without a naming
  collision (`setAuthRequired` in `table-registry-helper.ts` vs. a local same-named function
  inside `audit-fields-regression.spec.ts`'s own `test.describe` scope) — grepping for a bare
  function name across the repo is not sufficient to establish "who calls the shared helper";
  the actual `import` statements must be checked too.
- `coding-standards.md` (in `proj-ai-agentic`): comments are allowed (capped 1-2 lines, WHY only)
  specifically inside `api/utils/**`, `api/system_core/helpers/**`, and each module's own
  `helpers/`/`client/` folder — never inside `*.spec.ts` or `.env.example`, regardless of length.
