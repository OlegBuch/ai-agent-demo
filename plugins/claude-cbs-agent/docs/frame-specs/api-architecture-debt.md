# Known architecture debt in `api/`

## TL;DR

A full-repo audit (2026-09-15, ~150k lines / 215 non-test files across all of `api/`, Gather=Haiku
+ Judge=Opus per file) found **26 High / 58 Medium / 33 Low** findings. The micro-level discipline
is genuinely good — zero `any` anywhere in the whole `api/` tree, near-zero `!`, zero
`this.request.<verb>` escape hatches outside `BaseApiClient`, comment discipline is close to
perfect in specs. **The debt is structural**, concentrated in a handful of repeating patterns
below. Read this file before starting a new module, a large refactor, or anything touching
`api/utils/`, `api/types/`, or the Table Template projection-record path. Full per-area findings
tables live only in this session's chat/scratchpad and were not persisted verbatim — re-run a
targeted audit on the specific area if you need line-level detail beyond what's cited here.

## Judged healthy — do not "fix" these

- Zero `any` and (with one exception, `dm-helper.ts:31`) zero `!` across the entire `api/` tree.
- Zero `this.request.<verb>()` escape hatches outside `BaseApiClient` itself.
- `token-service.ts`'s per-`APIRequestContext` `WeakMap` caches (credentials, refreshed tokens, failure counts) — correct, GC-safe, exactly the documented token-lifecycle pattern.
- The `transfer` module's base-helper/regression-helper split — verified zero duplicated symbol names across all 3 pairs; the regression files correctly import primitives from their base rather than re-declaring them. Use this as the template when splitting other oversized modules (see #9).
- `fin_accounting` and `product_factory/negotiation_rules` as reference module shapes (client + helpers + tests + paths + values, each thin and single-purpose).
- `cce-fixtures.ts`'s discover-then-create-on-miss customer provisioning (`:82-113`) — the pattern hardcoded-environment-specific record IDs elsewhere in `product_factory`/`fin_accounting` should be fixed toward.
