# MR 202 — Logical Analysis (AQA + AQA Lead lenses)

TB-3197 — "Test impl: Access Administration - Regression" (Epic TB-20, Password Governance &
Lifecycle). Single author: Sergei Tsarik. Ticket has no description/Confluence page — the branch's
23 commits and the diff itself are the only stated intent.

## 1. Summary

The MR adds a brand-new `access-administration-regression.spec.ts` (2232 lines, 4 nested
`US-02.03.0X` Story blocks: Password Governance Configuration, Administrative Password Reset,
Lockout Management, Lock & Intent Management — 46 tests total) and extends six supporting files.
Test structure follows this repo's Story-scoped `describe` convention correctly, no `.skip`/`.only`/
stray `console.log`, and file-level cleanup (`afterEach` restoring `initialSystemParameterData`) is
sound. A full line-by-line pass (every changed line in the 6 support files, every test/step/assertion
in all 4 Story blocks) surfaced **9 Confirmed Issues, 11 Possible Risks, and 7 Nice-to-Have**
findings — a self-inflicted API-contract type, a duplicated enum, three separate clusters of
copy-pasted tests, several assertions weaker than what the test can actually prove, and a handful of
consistency/style gaps. Nothing found blocks the *architecture* of this MR, but several items
(#1, #3, #5, #8 below) should not merge as-is.

| 2 | Low (downgraded from Medium — see Changelog) | `waitBeforeReinitiatingIntent()` is unnamed/undocumented, but the underlying fixed wait is legitimate | `access-administration-helper.ts:35-37`, called at `...spec.ts:2075` (TC-3079) | **Author pushed back ("by test design, needed") — re-checked against the actual call site and the pushback holds.** TC-3079 (`...spec.ts:2053-2093`) captures `initialExpiresAt` from a first intent, waits, re-initiates the intent as the same user, then asserts the new `expiresAt` is *strictly later* than `initialExpiresAt`.
