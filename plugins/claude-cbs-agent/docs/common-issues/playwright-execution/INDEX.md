# common-issues/playwright-execution/ — Playwright test-runner behavior, reporting, and step-wrapping conventions

Part of `docs/common-issues/` — see the parent `docs/common-issues/INDEX.md` for the overall
cross-cutting-knowledge convention (when something belongs here vs. in a module folder, how to
add/update an entry, when to create a new file vs. extend an existing one).

## Entries

- [`test-callback-requires-destructured-fixtures.md`](test-callback-requires-destructured-fixtures.md) — `async (fixtures) =>` as a `test()` callback throws "First argument must use the object destructuring pattern" at load and kills every test in the spec file in seconds (tsc is clean); destructure the fixtures and pass an explicit object to helpers (2026-10-08).

- [`unwrapped-requests-outside-test-step.md`](unwrapped-requests-outside-test-step.md) — a helper call (currency minting, `finally`-block cleanup/restore, or a bare `beforeAll`/`afterAll` hook body) made directly outside a `test.step(...)` shows up as an unlabeled request in the Allure report; every such call, including cleanup and hooks, must be wrapped in its own named step — and a pervasively-called shared service function (`fetchKeycloakToken`, `createTestUser`/`deleteTestUser`) is worth fixing once at its own definition rather than at every call site. **2026-09-18 correction:** `test.step()` outside a test/worker context (`global-setup`/`global-teardown`, or a `{ scope: 'worker' }` fixture's setup/teardown) is a hard throw, not a no-op — a prior version of this file said otherwise; fixed via a shared `isInsideTest()` guard (`playwright-context-helper.ts`) in `fetchKeycloakToken`, `createTestUser`, and `deleteTestUser`, confirmed by a full repo-wide sweep of every worker-scoped fixture.
- [`expect-poll-step-explosion.md`](expect-poll-step-explosion.md) — Playwright's native `expect.poll()` auto-generates one Allure sub-step per polling attempt, exploding a single long wait into 100-220 near-identical steps; prefer the project's own `pollUntilReady` (no per-iteration steps) for passive read-only waits, keeping only the last 1-2 diagnostic attempts for the timeout error.
- [`playwright-worker-restart-on-failure.md`](playwright-worker-restart-on-failure.md) — a failing test restarts the worker before the next test in that file, re-running `beforeAll`; can produce a "Test not found in the worker process" report or unrelated-looking later failures around shared fixtures — check for an earlier failure in the same file before filing a later one as a new bug.
- [`playwright-error-message-embeds-call-log.md`](playwright-error-message-embeds-call-log.md) — a Playwright `APIRequestContext` error's `.message` carries a multi-line "Call log" **including the `Authorization: Bearer <token>` header** (and the raw `Error` object carries a full stack); never log the raw object/message or a hand-rolled `.split('\n')[0]` — use the shared `describeError`/`redactBearerToken` (`api/utils/helpers/error-format-helper.ts`), swept project-wide across ~24 files, 2026-09-03 (2 sites) / generalized 2026-09-04 (TB-3587).
- [`next-js-app-router-resourcetype-is-fetch-not-document.md`](next-js-app-router-resourcetype-is-fetch-not-document.md) — a same-app client-side route transition in this Next.js App Router UI never produces a `resourceType() === 'document'` response, only `'fetch'` (an RSC request with a `_rsc=` query param) — and the destination URL also matches on internal RSC redirect hops, so filter by `status() === 200` too. Only the very first post-Keycloak-redirect load is genuinely `'document'`.
- [`serial-mode-skips-remaining-tests-on-failure.md`](serial-mode-skips-remaining-tests-on-failure.md) — `test.describe.configure({ mode: 'serial' })` on a project already pinned to `workers: 1`/`fullyParallel: false` buys no isolation (that project has no parallelism to protect against in the first place) but still skip-cascades every later test in the group after one failure; check for a real shared-state justification before keeping it.
- [`table-registry-redirect-times-out-after-company-select.md`](table-registry-redirect-times-out-after-company-select.md) — a bare `expect(page).toHaveURL(...)` right after a navigation-triggering click inherits Playwright's un-configured 5000ms default unless the destination page object's own `waitForUrl()` is awaited first (this repo's established two-step pattern); a page object missing `waitForUrl()` (only exposing `assertUrl()`) is the tell. **Corrected same day:** the real fix belongs inside `SelectCompanyPage.selectCompany()` itself (it returns before the redirect completes) — patching only `company-selection.spec.ts`'s own call sites left every other caller (`loginAndSelectCompany`, used by `field-registry.spec.ts` and others) racing a hard `goto()` against the still-in-flight redirect.
- [`networkidle-goto-hangs-on-post-auth-pages.md`](networkidle-goto-hangs-on-post-auth-pages.md) — `waitUntil: 'networkidle'` on a `goto()` to an already-authenticated page can hang for the full `navigationTimeout` even though the page is fully rendered, because this app's shell retries a failing background projection read (`WORKSPACE.MENU~NAVIGATION` SEE, 404) indefinitely; use `'domcontentloaded'` plus the page object's own element-based `assertDisplayed()` instead.
- [`global-workers-pool-vs-per-project-cap.md`](global-workers-pool-vs-per-project-cap.md) — a project-level `workers` is a ceiling inside the root pool, not a reservation; computing root `workers` as a sum of per-project values (`API_TESTS_PARALLEL_WORKERS + API_TESTS_SINGLETON_WORKERS`) let `API-tests`/`API-tests-singleton` run concurrently even when the user asked for 1 total worker — fixed by making root `workers` the single knob and capping singleton at `min(N, 1)` (2026-09-17); 2026-09-25 added the two-sequential-invocation fix for true "singleton always last, alone" ordering, plus a non-bug addendum: with `fullyParallel: false`, actual workers used = `min(configured cap, matched files)` — passing a mixed singleton/non-singleton file list can route fewer files than expected to the main leg (via `testIgnore: SINGLETON_RECORD_SPECS`), making the printed `workers: API-tests=N` label overstate what will actually run.
- [`cutoff-buffer-test-computes-now-too-early.md`](cutoff-buffer-test-computes-now-too-early.md) — a test asserting "value inside a time buffer must be rejected" flaked because it computed `Date.now()` once at the top of the test instead of immediately before the request; any delay (auth retry, load) between the two erodes the margin before the value crosses the boundary and flips the expected result. Fix: compute the timestamp inside the same step that sends the request, and keep a comfortable margin from the boundary. Check for the same pattern in any other cutoff/buffer/expiry-window test.
- [`allure-runtime-parameter-lost-under-parallel-workers.md`](allure-runtime-parameter-lost-under-parallel-workers.md) — a module-level `apiTest.beforeEach(...)` in a shared fixtures file only ever attaches to the *first* spec file a given worker process loads (Playwright's `_hook()` binds to whichever file is mid-`require()`, and the fixtures module is only required once per worker) — every later file in that worker silently gets no hook at all, confirmed 100% deterministic per file (not a race) on real VM data, and it broke both a correlation-id report and Allure TestOps case linking (`allure.allureId()`) the same way. **Fixed** by converting the hook into a dependency-free `{ auto: true }` fixture instead (fixtures live on the shared `TestType`'s pool, not on a file's suite, so they survive any `.extend()` chain and any load order). **Two earlier fix attempts chasing a wrong "concurrency" theory for the same symptom were shipped and reverted same day — one broke test collection for the entire suite (0 tests ran)** because Playwright statically parses each test function's source text and requires a literal `{ ... }` destructuring first parameter; a generic wrapper function can't satisfy that. Do not retry wrapping the shared `test` export without first solving that constraint, per the file's own detailed writeup — the failure mode is total, not partial.
