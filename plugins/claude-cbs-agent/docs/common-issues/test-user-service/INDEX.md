## Entries

- [`test-user-service-empty-permissions-falls-back-to-minimal.md`](test-user-service-empty-permissions-falls-back-to-minimal.md) — `createTestUserWithoutPermissions`/`createTestUser({permissions: []})` silently grants `SM.USER:SEE` (the `MINIMAL` constant) instead of zero permissions, because the fallback check (`options.permissions?.length`) can't distinguish "not specified" from "explicitly empty" — found and fixed 2026-09-02.
- [`test-user-service-no-override-classes-option.md`](test-user-service-no-override-classes-option.md) — `createTestUser`/`createTestUserSession`'s `permissions` option only sets `PERMISSIONS` on the auto-created group, never `OVERRIDE_CLASSES`; build the group yourself and pass its id via the `groups` option instead of extending the service (TB-3587).
- [`test-user-service-external-classification-support.md`](test-user-service-external-classification-support.md) — `createTestUser`/`createTestUserSession` now support `classification: 'EXTERNAL'` (+ `allowedCustomers`), not just the original INTERNAL-only path; don't re-defer an EXTERNAL test-user need as a blocker (`integration_chapter`, 2026-09-07).
- [`test-user-service-group-cleanup-db-verified.md`](test-user-service-group-cleanup-db-verified.md) — DB-verified (`sm_user_group.liv/.nau/.his`, zero orphans) that `deleteTestUser`'s ad-hoc `SM.USER.GROUP~MAIN` `DELETE` genuinely purges the record, not just archives it — a colleague's separate stage permission-granting script reported the opposite ("group can't be deleted"), which is a real problem in a different, unrelated tool, not one `test-user-service` shares (2026-09-08).
- [`dashboard-user-never-sets-workspace-menu-root-id.md`](dashboard-user-never-sets-workspace-menu-root-id.md) — `provisionDashboardUser`/`createTestUser` never set `WORKSPACE_MENU_ROOT_ID`, so `WORKSPACE.MENU~NAVIGATION` SEE 404s for every UI-test dashboard user; observed once as the apparent trigger for a redirect-back-to-`selectCompany` on `company-selection.spec.ts`'s TC-210, but reproducibility/whether the app should tolerate this gracefully is still open (2026-09-09).
- [`test-user-service-companycodes-ignored-in-session-auth.md`](test-user-service-companycodes-ignored-in-session-auth.md) — `createTestUserSession`'s auth context ignored `options.companyCodes` entirely and always logged in under `process.env.COMPANY_CODE`; fixed to use `companyCodes[0]` as the active `X-Company-Code`, which made TB-3851 ("deleted record never reaches DEL") look like a backend bug when it was this test-side company mismatch (2026-09-11).
- [`enquiry-definition-see-404-for-disposable-test-users.md`](enquiry-definition-see-404-for-disposable-test-users.md) — executing a UI-wizard-created Enquiry 404s (`"Enquiry definition not found for id: ..."` from `definitions/enquiry/operation/SEE`) for any `createTestUser`-provisioned user regardless of `permissions` (tried `SEE`, then `TABLE ALL` + registry/language grants — no change) and regardless of a 60s backoff retry, but a real admin account hits no error doing the identical wizard flow by hand — same root-resolution class as the `WORKSPACE_MENU_ROOT_ID` gap below, exact missing field not yet identified; blocks TC-3123 (2026-09-23).
