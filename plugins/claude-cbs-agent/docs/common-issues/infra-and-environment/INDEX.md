## Entries

- [`bankuat-ui-base-url-host.md`](bankuat-ui-base-url-host.md) — UI on bankuat needs `BASE_URL=http://one.bankuat.local`; the bare `bankuat.local` host loses the session and every post-login deep link ends in `OAuthCallback` -> Home
- [`vm-sync-whitelist-silently-stranded-fixes.md`](vm-sync-whitelist-silently-stranded-fixes.md) — six compounding `run-on-vm.sh` reliability gotchas found 2026-09-07 through 2026-09-24: (1) the old explicit 9-file sync whitelist silently left any fix to an unlisted file running stale on the shared Azure `bankstg`/`bankuat` VM, now a full-tree `tar`-over-`ssh` sync (uncommitted changes included, no file whitelist) instead; (2) `watch_run()`'s `grep`-pipeline buffers non-line output over a pty-less `ssh`, so the live stream can lag minutes behind the VM's actual (fine) log - fixed with `--line-buffered`, but check `--status`/`run.log` before assuming a console gap means a hang; (3) `CBS_VM_ROOT` copied verbatim from a teammate's own `.env.bankstg-local` points at a `750` directory only *they* can write - always per-engineer, never copied; (4) a brand-new personal `CBS_VM_ROOT` has no `node_modules` at all (deliberately never synced from a workstation) and fails `Cannot find module 'dotenv'` - now auto-seeded server-side from `/opt/perftest/aqa` by a new `ensure_node_modules()` step; (5/6, 2026-09-24) `watch_run()`'s stream is a content *allow-list*, not a passthrough - a normal `console.log` that doesn't match its regex is silently dropped from the terminal (but still lands in the fetched `run.log`), and separately a log line deep in a fixture can look "missing" simply because an earlier dependency fixture (e.g. `workerSuperAdmin`) already threw and the code never reached it - check what actually ran before suspecting sync/build.
- [`env-example-stale-vs-user-credentials-values.md`](env-example-stale-vs-user-credentials-values.md) — **SUPERSEDED (historical; `user-credentials.values.ts` and the Vault bootstrap script are gone).** `.env.example` is missing several env vars that `api/utils/constants/user-credentials.values.ts` actually reads (`SUCCESSFUL_USER_ID`, `CHECKER_USER_ID`, `RESTRICTED_USER_ID`, `TR_*`, `PAYMENT_ORDER_*`); grep `user-credentials.values.ts` itself, not `.env.example`, to scope any hardcoded-test-user audit (TB-3587).
- [`kafka-ui-proxy-transient-failures.md`](kafka-ui-proxy-transient-failures.md) — the Kafka UI REST proxy intermittently times out (`readLatestMessages`) or resets the connection (`deleteKafkaTopicsForTableIds`), same non-bug pattern as Keycloak-under-load; `readLatestMessages` now retries transient failures 3×/1s, `deleteKafkaTopicsForTableIds` still doesn't (known gap, TB-3587, 2026-09-03).
- [`dispo-officer-vault-provisioning-pipeline.md`](dispo-officer-vault-provisioning-pipeline.md) — **SUPERSEDED 2026-10-01 (Vault pipeline and `bankstg-provision.sh`/`bankstg-bootstrap-env.sh` deleted; historical).** `DISPO_OFFICER_SECOND/THIRD` aren't just hardcoded env vars: `bankstg-provision.sh` creates/rotates their Keycloak accounts via a dedicated Vault-backed pipeline, and `override-dispo-smoke.spec.ts` reuses them as one shared, mutated-in-place fixture across ~20 interdependent routing/escalation tests (47 call sites) — not 4 isolated cases like `PARTIALLY_ACCESS_USER`; migrating them is an infra-spanning decision, not a scoped code fix (TB-3587, 2026-09-07).
- [`local-cleanup-vs-preserve-debug-flag.md`](local-cleanup-vs-preserve-debug-flag.md) — `LOCAL_CLEANUP` only gates `db-helper.ts`'s schema/table-group cleanup; several suite helpers (`ddi-helper.ts` and 4 siblings) have their own record tracker gated by a separate `PRESERVE_LOCAL_GROUP_FOR_DEBUG` flag instead, and `run-on-vm.sh` composes the VM's `.env` from `.env.<env>-local`, never from the repo's own `.env` (2026-09-10).
- [`pod-restart-leaves-async-pipeline-cold.md`](pod-restart-leaves-async-pipeline-cold.md) — after `table-registry-helper.ts` forces a pod restart for Liquibase migrations on a freshly-created table, "table recognized by pod" (metadata-level) doesn't guarantee downstream async pipelines (e.g. DEL-segment purge) are equally warm yet; hit a tight 15s `expect.poll` in Customization's DEL-purge precondition (2026-09-11) — widened to `timeout: 45000` + `intervals: [5000]` rather than adding a hardcoded sleep.
- [`pf-balance-type-wash-chrg-account-missing.md`](pf-balance-type-wash-chrg-account-missing.md) — `PF.BALANCE.TYPE` is missing the `WASH-ACCOUNT`/`CHRG-ACCOUNT` reference rows on bankstg, so any charge or cross-currency transfer fails Posting Engine AUTH with a `422` wrapped in a `400`; reproduced identically in two same-day bankstg e2e runs (2026-09-16) — not transient, needs seeding.
- [`reconciler-offline-flag-poisons-rest-of-worker-run.md`](reconciler-offline-flag-poisons-rest-of-worker-run.md) — `table-registry-helper.ts`'s "Database reconciler is offline/down" is a client-side circuit-breaker flag file: one genuine Postgres schema/space poll timeout on any table poisons every other table-creation call in the *same worker* for the rest of the run; 10 Customization/Idempotency/Currency failures across smoke+regression (2026-09-16/17) were 1 real incident + 9 cascading noise, not 10 separate bugs.
- [`kafka-topic-env-prefix-uses-env-target.md`](kafka-topic-env-prefix-uses-env-target.md) — every Kafka topic name (CBS `<env>.<tableId>` or `cce-values.ts`'s `proj.*` audit topic) uses the typed helper `getCurrentEnvName()` (`test-ownership.ts`, derives from `DB_NAME`'s suffix) — `ENV_TARGET` is a separate CI-pipeline var, Allure-tagging-only after this incident; Consolidation Engine's 15 call sites had invented an undefined `CBS_ENV_NAME`, producing a literal `"undefined.CM.CUSTOMER"` 404-retry flood for up to 90s per test (2026-09-18) — fixed to `getCurrentEnvName()`, and `cce-values.ts`'s pre-existing `ENV_TARGET` usage switched too; `ENV_TARGET` also added to `.env.bankstg-local(.example)`/`.env.bankuat-local(.example)` since it was separately missing there (still needed for Allure's environment tag).
- [`opensearch-correlation-id-index-not-populated-non-dev.md`](opensearch-correlation-id-index-not-populated-non-dev.md) — `proj-correlation-id-starter` confirmed to log under OpenSearch field `app.correlationId` on index pattern `proj-<env>`, but `proj-stg` (and every env except `proj-dev`/`proj-uat`) appeared to have no recent logs at all as of 2026-09-24 — open, unconfirmed root cause (suspected index templates not deployed to non-dev), platform team investigating; test-side header propagation was independently verified correct first, don't assume a missing OpenSearch hit means the test didn't send the header.
