# common-issues/test-data-and-assertions/ — Test-data generation, payload shape, and assertion-writing conventions

Part of `docs/common-issues/` — see the parent `docs/common-issues/INDEX.md` for the overall
cross-cutting-knowledge convention (when something belongs here vs. in a module folder, how to
add/update an entry, when to create a new file vs. extend an existing one).

## Entries

- [`smoke-case-filed-wrong-suite-file.md`](smoke-case-filed-wrong-suite-file.md) — check every test case's own `Type` column (Smoke vs Regression) before filing a new `US-XX.YY.ZZ` block into `*-regression.spec.ts`; a Smoke-typed case belongs in the sibling `*-smoke.spec.ts` file even when it shares a Story with Regression-typed siblings.
- [`raw-body-toContain-for-error-messages.md`](raw-body-toContain-for-error-messages.md) — assert error-message content via `extractErrorMessage(parseErrorBody(resText))` (`response-parser.ts`), not `toContain()` against the whole raw JSON body — the latter can match the wrong field and dumps the entire envelope into failure diffs. For a hook-validation error (`detail` is only the generic wrapper, the real reason is in `properties.errors.<FIELD>`), use the sibling `extractPropertiesErrorMessage(...)` instead.
- [`table-create-auditable-field-removed.md`](table-create-auditable-field-removed.md) — the backend dropped `auditable` from `POST /table-registry/api/v1/tables`'s accepted schema entirely (confirmed by dev chat and by `proj-bruno-api`'s Table Registry docs — it's now derived from `type`, never client-settable); sending it at all now gets a `400 "unknown field 'auditable'"` that cascades into skipping every later test in the file. Removed from `CreateTablePayload` and every call site that still passed it (`buildCreateTablePayload`, override-dispo, table-registry, validation-engine, audit-fields specs).
- [`random-id-can-collide-with-real-reference-data.md`](random-id-can-collide-with-real-reference-data.md) — a randomly-generated id from a small fixed alphabet (e.g. 3-letter currency codes) can collide with real pre-seeded reference data; a "this must not exist" negative-test fixture needs an existence check, not just a creation-time collision retry.
- [`jackson-lenient-scalar-to-boolean-coercion.md`](jackson-lenient-scalar-to-boolean-coercion.md) — a JSON number sent for a `boolean` field is coerced (`0`→`false`, nonzero→`true`, `200`), not rejected like an arbitrary string (`400`); don't assume both "wrong type" cases fail the same way.
- [`mint-random-value-once-not-per-call.md`](mint-random-value-once-not-per-call.md) — never call `generateRandom*()` inside a payload-builder closure invoked more than once for the same logical record (breaks immutable-field invariants); mint once outside and reuse, and prefer a collision-retrying helper (`createDedicatedCurrency`) over a bare one-shot generator for a small-value-space field (found via a self-inflicted bug, 2026-09-03).
- [`no-provenance-citations-in-test-code.md`](no-provenance-citations-in-test-code.md) — a `test.step` title or `expect()` message must never cite a ticket number, Allure case id, doc, or date as justification (`per TB-3588's...`, `per allureCaseId(N)'s own Expected Result: ...`) — strip the citation, keep only the plain fact; found recurring across 6 spec files 2026-09-03.
- [`required-field-omitted-vs-empty-value-are-different-checks.md`](required-field-omitted-vs-empty-value-are-different-checks.md) — a schema-level `required` check only tests key presence, a business-rule "must be empty" check only runs after it and tests the value; a suite that always sends the field (even as `''`) never exercises the omitted-key path, no matter what a "no `<FIELD>`" test's title claims (TB-3588).
- [`antd-dropdown-option-label-can-carry-a-parenthetical-suffix.md`](antd-dropdown-option-label-can-carry-a-parenthetical-suffix.md) — the shared `antd-virtualized-dropdown.ts` exact-match helper only tolerates a dash-separated `"VALUE - description"` suffix, not a parenthetical `"VALUE (description)"` one (e.g. the company selector's `"MOCK (UTC)"`); a page-specific assertion/selection helper must strip that suffix itself, never assume the shared helper already covers it.
- [`antd-multi-select-dropdown-stays-open-after-selection.md`](antd-multi-select-dropdown-stays-open-after-selection.md) — `selectComboboxOption()` never closes the dropdown after clicking an option; fine for single-select (AntD auto-closes) but a multi-select filled via a loop of calls stays open afterward and its rendered option list can intercept later clicks (e.g. a submit button) — close it explicitly (`Escape`) once done.
- [`batch-input-record-shape-is-fields-not-data.md`](batch-input-record-shape-is-fields-not-data.md) — the new split batch INPUT endpoints (`/api/v1/batch/{full|partial}/projections/:projectionId/records/operations/INPUT`, TB-3337) require each record as `{ recordId, seqNo, fields }`, not the single-INPUT `{ recordId, data }` shape `buildRecordInputPayload` returns; response shape also changed (`items`/`result` instead of `results`). Found in MR !225 (2026-09-11): the URL migrated correctly but the payload didn't.
- [`sector-hardcoded-in-customer-payload-builders.md`](sector-hardcoded-in-customer-payload-builders.md) — `CM.CUSTOMER~RETAIL.INPUT`/`~CORPORATE.INPUT` now reject any payload containing a `SECTOR` key at all (`NO_INPUT` behavior), but `buildRetailCustomerInputPayload`/`buildCorporateCustomerInputPayload` hardcode `SECTOR` into their `data` object before `...overrides` — a caller can change the value but never omit the key. Reproduced in two same-day bankstg runs (2026-09-16) across 4 `customer-party-integration.spec.ts` tests.
