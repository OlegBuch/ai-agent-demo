# CBS — Core Banking System project context

Teaches Claude the CBS core's architecture, terminology, and operational model. Full detail lives in `references/system-core.md`, kept separate so this entrypoint stays cheap to auto-load.

## When to load

Load on CBS-specific signal: **Table** (logical service unit, not DB table), **Projection**, **Inquiry**, **INT/FIN/CUS**, **`NAU`/`LIV`/`HIS`**, **4-eyes approval**, **Field/Table Registry**, **Plugin Manager**, **Table Template**, **Plugin API**, **`executeRecordOperation`**, **Record Intent** (record locking), **Hooks** (pre/core/post), **`hookOutcome`**, **`dataRecord`**, **`tableClient`**, **Master vs Branch Company**, **multi-marker field**, **Table Group**, **seeding**, or work in a CBS repo (`table-template`, `Plugin API`, Field/Table Registry, Plugin Manager).

Also load on CBS **security/authorization** signal — then offer the SMS reference (below): **SMS** (Security Management System), **`SM_USER`**/`USER` table, **`sub`**-keyed identity, **AuthZ service**/`ext_authz`, **Data Access** (record/field), **`SM_USER_GROUPS`**/groups, **Override classes**, **permission whitelist**, **`CBS-User-Context`** header, or user provisioning via Keycloak + INPUT.

Also load on CBS **product/catalog** signal — then offer the Product Factory reference (below): **Product Factory**/**PF**, **Attribute Class**/**Attribute**, **Product Class**/**Product Type**, **Builder**/**Manager**/**Catalog** Tables, **`DRAFT`/`VALIDATED`/`CATALOG`** status, **conditions** (vs abstract attributes), **attribute types** (`CCY`, `DATED`, `MULTIPLE`, `MERGE`, `TRACKING`, `FORWARD.DATED`, …), or **parent product**/inheritance (**override** vs **merge**).

Also load on CBS **contract/product-operation** signal — then offer the Product Factory contracts reference (below): **contract** (vs product), **Contract Operations Engine**/**COE**, **`PF.CONTRACT.OPERATION`**, **operation class** (`ACCOUNT-CREATE-CONTRACT`, `ACCOUNT-CHANGE-INTEREST`, …), **`PF.ATTRIBUTE.CLASS.ACTION`**/class action type, **initiation type** (`USER`/`TRANSACTION`/`COB`/`API`/`CHILD`), **`PROCESS.DETAILS`**/**movements**, **negotiation rules**/**`COMPARISON.TYPE`**, **`PF.PRODUCT.*.CONDITION` vs `PF.CONTRACT.*.CONDITION`**, **resolved conditions** vs **active conditions**, **tracking**/**`PRODUCT.TRACKER`**/product version cascade, **operation-level authorization**, **`CONTRACT.DETAILS`**/contract status (`CURRENT`/`INACTIVE`/`DORMANT`, `DORMANCY.CONDITION`), **`isContractCreation`**/**`keepHistory`**/**`allowedInitiationTypes`**, **`operationPayload`**, operation status (`pending`/`in progress`/`done`/`error`/`override`), **child/secondary operations** and the one-level nesting cap, one-operation-in-flight, or **`DM.TRANS.DOCUMENT`** gating a contract going `LIV`.

Also load on CBS **customer/party** signal — then offer the Customer reference (below): **Customer**/**Party**, **`CM.CUSTOMER`**, prospect/**`CM.MISC.PARTY`**, **relationships** (`CM.CUSTOMER.RELATIONSHIP`/`CM.RELATION.TYPE`), **prospect promotion**, **KYC/AML**, customer **document obligations** (`DM.CUST.DOCUMENT`, `missing`/`received`/`verified`, `DM.DOC.RULE`, `DM.DOCUMENT.UPLOAD` + pre-signed S3 URLs), **external user** attachment (`SM.USER` `EXTERNAL` + `ST.ROLE`), or the **EP-03.01** / **3rd Party Hooks** specs.

Also load on a **concrete Table ID** signal — then offer the Table catalog reference (below): a dotted business-Table id such as **`SYSTEM.PARAMETER`**, **`COMPANY`**, **`SM.USER`**, **`SM.USER.GROUP`**, **`SM.DATA.ACCESS`**, **`ST.ROLE`**, any **`CM.*`**, **`DM.*`**, **`PF.*`**, **`IC.*`**/**`CC.*`**, or an id from the wider module map (**`CURRENCY`**, **`COUNTRY`**, **`CONTRACT`**/**`ACCOUNT`**, **`*.CONDITION`** attribute-class Tables, **`JOURNAL.ENTRY.AL`/`.PL`**, **`PAYMENT.ORDER`**, **`FUNDS.TRANSFER`**, **`LIMIT`**, **`TELLER.ID`**, …) — or "which Tables exist / live in &lt;group&gt;".

Also load on CBS **interest/charges (I&C)** signal — then offer the Interest & Charges reference (below): **Interest Calculation Engine**/**IC Engine**, **Charge Calculation Engine**/**CC Engine**, **`Basis Amount`**, **`GLOBAL.INTEREST.RULE`**, **`GLOBAL.CHARGE.RULE`**, **`CHARGE.TARIFF.GROUP`**, **`BENCHMARK.REFERENCE`**, **`FLOATING.BASE.RATE`**/**`PERIODIC.INTEREST`**, **`INTEREST.BASIS`** (day-count), **`RATE.TYPE`** (`FIXED`/`FLOATING`/`PERIODIC`), **tiering** (`SINGLE`/`LEVEL`/`BAND`), **spread sequence**, **tariff group**/**`RULE.GATEWAY`**, **stateless calculation engine**, or the **13.01**/**13.02** specs.

Also load on CBS **payments/transfers** signal — then offer the Transfers reference (below): **Payment Order**/**`PAYMENT.ORDER`**, **`PAYMENT.ORDER.PRODUCT`**/**`PAYMENT.ORDER.PARAMETER`**, **Funds Transfer**/**`FUNDS.TRANSFER`**, **`FT.TXN.TYPE.CONDITION`**, **`INTERNAL.FT`**/**`EXTERNAL.HUB`** (connection method), **warehousing**/**`WAREHOUSED`**, **`PENDING_COMPLIANCE`**/**`AWAITING_ACK`**, **charge bearer**, **mandate reference**, **credit transfer vs direct debit**, **instruction ID vs end-to-end ID**, **value date vs booking date**, **Posting Engine**, **Financial Crime Management System**/AML adapter, **`route-to-transfer`**/auto-auth plugin, or the **08.01**/**08.02** specs.

Also load on CBS **posting/accounting/balances** signal — then offer the Financial Accounting reference (below): **Posting Engine**, **entry**/**leg**, **`EG.JOURNAL.ENTRY`**, **AL vs PL**, **debit/credit direction**, **narrative**/**`POSTING.DETAIL`** (static/payload/link-table), **Transaction Reference**/**source system**, **reversal marker `R`**/**`TRANSACTION.REVERSAL`**, **Balance Engine**, **`AM.ACCOUNT.BALANCES`**, **Working/Cleared/Available Balance**, **balance type**/**sub-ledger bucket**, **`IN_PROGRESS`**/**`ACTIVE`** balance status, **Consolidation Engine**, **`CONSOLIDATE.COND`**/**consolidation keys**/**dimensions**/**data cube**, **ClickHouse**, or the **`Money`** type (**currency**/**units**/**nanos**).

Skip for: generic Java/Spring/Kafka/Postgres with no CBS signal, or Bruno YAML (the bundled `bruno` skill handles that).

Load once per session, then stay loaded — don't reload on follow-ups.

Vocabulary: when "Tables" is ambiguous, say **business/service table** vs **database table** explicitly.
